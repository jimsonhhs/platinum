# 分段写作：逐段生成 + 段级评审（创作 / 润色 / 复制润色 / 定点润色）

## 执行纪律（必须遵守，减少无效动作）

1. **禁止擅自创建结构化数据**：正文创作过程中不得创建角色、地点、伏笔、时间线条目等任何数据（create_* / update_* 一律不动）。正文需要新角色/新设定时，先用通用占位描述（如"圣骑士""老猎人"）继续写，**不要停下来设计名字、背景、性格**；维护阶段再询问用户是否要正式创建。
2. **输出遵守常驻《重点分段》规则**：writer 写出的段落直接按短段输出（≤3 行/段，重点独立成段），不要事后整篇重排；该规则机械执行，不参与 review 评审。
2. **不要做长篇设计推导**：不起名、不纠结世界观细节、不反复推演"该不该"——直接按大纲写。大纲没写的东西默认不写。
3. **已有正文 → 默认润色**：目标章节文件已有内容（非空）时，用户说"写/处理/改/修第X章"默认进入**润色模式**（在已有内容上逐段优化），不要从头重写，不要推导半天。用户明确说"重写"才重写。
4. **"A 内容 → B 文件"指令 = 复制润色**：用户说"把 [来源] 的内容润色/改写/输出到 [目标]"时，立即执行：read 来源文件 → 润色 → 写入目标文件。**来源文件只读，绝不修改**（这是用户保护原文的意图）。不要反复确认、不要解释流程，直接干。
5. **编号规则**：用户指令里的纯数字（"007""第7章文件"）优先按**文件编号**理解（chapters/007.md）；中文"第X章"按章节号理解。两者可能不一致（历史数据里编号有位移），歧义时快速 read 文件首尾确认一次即可，**不要长篇推导**。
6. **冲突即停（仅严重冲突）**：写作/润色过程中，仅当发现**严重冲突**——正文与大纲完全无关（核心事件/主题毫无体现，走向完全是另一回事）、或直接矛盾（人物命运相反、关键事件结果相反、重要设定冲突）——才立即中断，一两句话摆出冲突问"保持现状 / 改正文 / 更新大纲"。**轻微差异（细节出入、顺序调整、补充、节奏）不触发**，继续写，可在汇报里顺带提一句，不要频繁打断。严重冲突时禁止自行推断意图继续写、禁止擅自选一边。
7. **行号定位与按需读取（省 token 铁律）**：用户给出"章节 + 行号范围"（如"润色006的25-59行"）时，用 read 的 start_line/end_line **只读目标行范围**（工具自动标注原始行号，无需读全文）；需要背景时按需读取相关部分（目标段前后文、真实前情章），涉及人物设定时用 get_* 精确查询。**行号是默认入口，不是禁止读全文**——当内容依赖设定/上下文时，按需读必要部分。用户复制原文且未给位置时：默认这段不在任何章节文件中，**禁止尝试定位到章节**（避免全文搜索浪费 token）。

## 触发边界（重要）

本技能**只在产出或修改正文时使用**（写新正文、按意见改正文、润色成品）。纯讨论剧情、构思、问答、规划（"这个角色后面怎么办""帮我想想情节"）时**不要**启动分段-评审循环，正常对话即可。用户明确要求"用分段写作"时才进入本流程；判断不准时先问用户。

**润色与大纲的关系（铁律）**：用户说"润色/优化/改改文笔"时，**正文是唯一依据**——不得读取或参考用户大纲（user_outlines/NNN.md）来改正文，不得把大纲内容（尤其是过时的）带进正文，不得触发一致性比对。只有用户明确说"按大纲改""按照大纲写"时，大纲才作为修改依据。

## 核心原则

- 单次生成上限约 300 字。
- **被润色的原文永远标记为"原文/待改对象"，不是背景**：润色类任务的评审基准是原文（信息忠实度 + 表达提升），不是前情一致性；前情只指"原文之外的真实故事背景"。混淆这两者会导致评审把来源当背景、浪费推理并误判。
- 生成端和评论端是两个角色，不允许互相代劳：生成端不辩护，听到毛病就改；评论端只挑刺，不帮写。

## 模式一：创作模式（从大纲写新正文）

1. **拆解大纲**：读取本章正文大纲（outlines/NNN.md）和本章用户大纲（user_outlines/NNN.md，若存在必须遵守）。把大纲拆成 3-8 个小节拍（每个约 300 字：一个场景内的一段动作/对话/心理），在心中排好顺序。若有"设定先行"要求（角色/地点先查工具确认），在动笔每个小节拍前完成。
2. **写入草稿，不写正文**：本章正文一律写入草稿 drafts/NNN.md（AI 无权限写 chapters/，工具已强制拦截）。草稿为空/不存在时：若正文已有内容先调 copy_to_draft 本地初始化，或直接 edit 创建草稿；**草稿已有内容时用 line_range_replace 追加/修改，禁止 full_replace 重写全章**（除非整章重写场景）。
3. **三段独立执行**：你（主控 Agent）只负责拆解任务和转达意见，**写文交给 writer 子 Agent，评审交给 review 子 Agent**：
   - 写文：`run_subagent(agent_type=writer)`，指令中包含：大纲片段（或当前段要求）、上一段结尾（保持承接）、要写入的文件路径（drafts/NNN.md）、只写当前小节拍（≤300 字）、写作前用 get_*/read 确认涉及的角色/地点设定。writer 完成后返回写入结果。
   - 评审：`run_subagent(agent_type=review)` 评审**刚生成的这一段**（不是全文！）。任务里明确：只评审我给出的这一段；以"第一读者"视角，按下方《评审清单》挑刺；只挑刺不代写；每条意见注明位置+原因+改法。如该段涉及强烈情绪或行为合理性，先 read 行为推演技能，把其清单并入评审标准。
   - 循环：writer 写 → review 评 → 把意见原样转给 writer 修改（writer 只改指定段落，不辩护）→ review 复评 → pass 则定稿写下一段。
4. **兼容退化**：若 writer 子 Agent 不可用（报错），由你直接写草稿，但评审仍必须用 review 子 Agent，不得自己评自己。
5. **循环上限**：同一段最多 5 轮。5 轮未过，把最新意见原样呈现给用户并停下询问，不硬凑。
6. **章级评审**：整章草稿完成后启动 review 子 Agent 做章级审读（跨段连续性、情绪曲线、伏笔咬合、删段损失），逐条处理意见后向用户汇报。
7. **发布**：章级评审通过后，**询问用户是否导入正文**（"草稿已完成，是否导入为第N章正文？"）；用户确认后调 import_draft 工具，或提示用户点"导入正文"按钮。未确认前不得导入。
8. **维护**：导入后按系统维护流程执行（角色/时间线/弧线/读者认知/章节计划），并**同步本章正文大纲**（outlines/NNN.md 按正文实际内容更新；禁止篡改 user_outlines/NNN.md）。

## 模式二：润色模式（对已有成品）

用户给成品要求润色、或说"这段不行"时：

0. **正文是唯一依据**：润色全程以现有正文为准，不读用户大纲、不比对大纲、不改剧情走向（除非用户明说）。改的是表达，不是内容；内容层面的问题（如逻辑漏洞）只报告给用户，不擅自改。

1. **先分段，不急着改**：读取目标章节全文，用 2-3 句话概括为若干小节拍（每个约 300 字），先在回复里列出分段清单，确认或直接开始。
2. **复制润色（A→B，用户保护原文的用法）**：当用户说"把 [来源] 的内容润色/改写/输出到 [目标]"时：只读来源文件（如 chapters/006.md），润色结果写入目标文件（如 chapters/007.md，不存在则创建，title 用章节标题）。**来源文件一字不动**；目标文件已存在则在目标上继续。若目标是新章号，正文大纲可待润色完成后同步生成，不动来源章的大纲。
   - **同章润色默认输出到草稿（drafts/NNN.md）**：用户只说"润色第X章"（未指定目标）时，润色稿写入本章的草稿文件 drafts/NNN.md——不新建章节、不动正文、不进维护。用户满意后由用户点"导入正文"覆盖本章正文，或用户明确说"直接写回正文"时才写 chapters/NNN.md。A→B 跨章时若目标未指定章号，同样默认写目标章的草稿。
   - **原文 ≠ 前情（关键，防止评审把来源当背景）**：给 writer 和 review 的指令中必须显式标注——【来源文件内容 = 待润色的原文，不是故事前情】。评审以**原文**为基准做"信息忠实度 + 表达提升"判断（不丢信息、不加戏、表达更好），**不得**把原文当背景做"前情一致性"判断。
   - **上下文规则**：A→B 时若来源章就是"上一章"，**不再把来源章内容当上下文注入**（否则就是"原文 vs 背景"自相混淆）；需要衔接时，用 get_chapter_list 读取来源章的 prev_chapter_number（真实上一章，跨空洞），读其结尾作为前情（如 006 的上一章是 005，取 005 结尾），或明确告知"本章为独立润色稿，无前情"。
3. **逐段润色**：一次只处理一个小节拍。先让审稿子 Agent 对该段挑刺（同一段评审协议），再按意见重写该段，写完交给同一段复评。pass 后进入下一段。
4. **章级复审**：全部段落润色完后，做一次整章复审（连贯性、风格统一、信息一致性），并**输出本章大纲差异**（润色后正文与 outlines/NNN.md 的出入点），据此同步正文大纲。
5. 润色模式不动用户大纲，不创建任何角色/设定数据。

## 模式三：定点润色（只改一小段，不扫全文）

用户想只优化某一小段文字、用迭代方法、但需要上下文衔接时（"帮我润色这一段，不要动其他的"）：

1. **锁定目标**：用户给出章节 + 段落（引用原文 / 说"第X段" / 指位置）。先 read 章节文件定位该段，把目标段原文引用出来确认（用户明确说直接开始则跳过确认）。
2. **只取上下文，不扫全文**：只读取目标段的**前一段 + 后一段**（或前后各 200-300 字）作为衔接约束。**不读取全文、不拆整个章节、不触发章级评审**。
3. **迭代改写**（writer/review 循环，同段级评审协议，上限 5 轮）：
   - 写文：run_subagent(writer)，指令含：目标段原文 + 上文结尾 + 下文开头 + 要求（保持衔接、不改变剧情走向与信息量、只优化表达/节奏/细节）。
   - 评审：run_subagent(review) 只评这一段改写稿，额外检查三点：接得住上文、指向下文、不引入与上下文矛盾的信息。
   - 意见转 writer 修改 → review 复评 → pass。
4. **只改这一处**：定稿后用 edit（search_replace 或 line_range_replace）替换回原文件，其余内容一字不动。
5. 不改剧情、不创建数据、不动大纲（需要时另行说明）。

## 评审清单（段级，审稿子 Agent 逐项对照）

1. 状态：每个行为结合角色当前状态了吗（情绪/体力/处境/对谁说话）？
2. 性格：符合这个人的底色吗？（不是作者的底色，不是读者的期待）
3. 因果：承接已发生的事了吗？先有动机后有行为，不能先行为后补动机。
4. 处境：这个环境里他可能这么说/做吗？
5. 台词：接得住上一句、指向下一句吗？悬空就删或重写。
6. 视角：谁的主视角就用谁的眼睛看（"林茵看见她指节发白"，不是叙述者跳出来写"她指节发白"）。
7. 措辞：准确具体，不故弄玄虚。
8. 信息：作者借角色嘴科普了吗？信息要"要来的"，不是"塞的"。

## 收尾自检（每段定稿前）

1. 这段每个行为，我能说清"他为什么这么做"吗？说不清就重写。
2. 删掉这段对角色/情节影响大吗？只对世界观有信息价值、对角色毫无推动的，删除或转移。
3. 情绪有真实推进吗（A→B 有因果）？情绪没变化的行为段是过渡，不该占正戏位置。
