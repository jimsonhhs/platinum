# 重点分段：短段优先，重点独立成段

## 为什么

读者扫读时，注意力只落在每段（每行）开头的几个字。长句长段会快速分散注意力，核心重点被淹没。因此：**重点必须独立成段，短段优先**。

## 快速分段判定（机械执行，禁止自我论证）

**命中即拆，不用想"重不重要"**——只要出现以下信号，就把该句/该重点独立成段：

1. **转折**：但 / 然而 / 可是 / 却 / 偏偏 / 谁料 / 没想到
2. **结论或顿悟**：所以 / 因此 / 这说明 / 原来 / 原来如此 / 这才明白 / 忽然懂了
3. **情绪爆发**：惊 / 怒 / 喜 / 绝望 / 恐惧 / 震怒 / 狂喜 / 心一沉 等强情绪句
4. **关键信息**：名字 / 时间 / 地点 / 数字 / 秘密 / 真相 首次出现时
5. **对话**：说话内容独立成段；重要台词后可留白一行

**没有信号也拆（长度即拆）**：

6. 单句超过约 40 字 → 按意群断成短句（在主谓、转折、因果处断）
7. 段落超过约 3 行（60 字）→ 按内容重点拆成两段以上

**默认节奏**：宁可多拆，不可不拆。短段优先是常态，不是例外。

## 执行纪律

- **先询问后执行**：用户抱怨分段或要求调整分段时，先确认"是否按重点分段规则处理？"，用户同意后再动手；不擅自全文重排。
- **只改分段与断句，不增删改写内容文字**（可微调标点配合断句）。
- **完成后简短说明改了什么**（如"已把长段按重点拆为短段"），不逐段汇报。
- **写作时直接按此规则输出**（writer 写出来就是短段），不要事后整篇重排；润色/导入前定稿时一次性检查一遍即可，不反复循环。
- **不拆**：代码块、引用块、大纲/计划类文件、用户明确要求保留的长段。
- **用户显式指定格式时，以用户为准**。
- 与 review 的关系：review 只评内容与表达，不评分段；本规则不进入 review 清单，review 通过后由定稿方直接套用。
