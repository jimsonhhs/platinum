# 多章创作：自动编排的持续创作流水线

## 触发条件

用户给出大体方向/核心情节，明确要求连续创作多章（"按这个方向写下去""写10章""继续往下写"）。单章创作走分段写作，本技能负责**多章编排**。

## 流程

1. **整体规划**：读取用户大纲（user_outlines/，如有）、设定（setting）、弧线/时间线现状。把用户给的方向沉淀为整书剧情规划：写入 plans/（next/near/far）或创建/推进 story_arc 节点。规划要点：主线、阶段目标、伏笔布局（只规划，不擅自创建角色/设定数据）。
2. **逐章大纲**：按规划迭代出每章大纲，写入 **outlines/NNN.md**（正文大纲，AI 有权限）。自动模式下无需逐章审批；如用户设置了手动审批，走审批流。
   - **用户大纲的边界**：user_outlines/ 是用户意图层。AI 默认不写；若用户明确要求"你来规划章节意图"，AI 可以**起草** user_outlines/NNN.md，但必须标注"AI 起草，待用户确认"，且不得在用户确认前把它当已生效意图执行。
3. **逐章正文（调用分段写作）**：每章正文一律写入草稿 drafts/NNN.md，按分段写作的三段独立迭代执行（主控拆解 → writer 分段写 → review 段级评审 → 复评 → 定稿）。**禁止直接写 chapters/**。
4. **章级发布**：每章草稿完成后询问用户是否导入（或用户预先授权"写一章导一章"）；导入用 import_draft（文件级，零生成 token）。导入后执行维护（角色/时间线/伏笔/弧线/读者认知/章节计划）+ 同步正文大纲，然后进入下一章。
5. **整书评审**：全部章节完成后，启动 review 子 Agent 做跨章评审（连续性、情绪曲线、伏笔咬合、节奏分布），逐条处理或汇报。

## 规则

- 每章完成后维护是强制步骤（含同步 outlines/NNN.md），不得跳过。
- 上下文与行号：跨章引用前情用 prev_chapter_number 或 search_story_memory；行号指令歧义（草稿 vs 正文）先确认。
- 迭代上限：每章分段循环 5 轮上限；整书创作若中途需要用户决策（方向冲突、设定分歧），停下询问，不擅自改方向。
- 破甲词与守则始终生效。
