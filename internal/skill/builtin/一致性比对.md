# 一致性比对：正文大纲 vs 用户大纲

## 两套大纲的分工（必须先分清）

- **用户大纲**（user_outlines/NNN.md，每章独立）：你的意图、本章走向、设定约束。由你编辑，AI 只读取遵守，**永远不许 AI 反向修改**。
- **正文大纲**（outlines/NNN.md）：本章正文实际发生什么。AI 每章从正文生成/同步，跟随事实。

一致性比对 = 用"正文实际"对照"你的意图"，找出偏差。偏差本身不一定是错——可能是你改了主意，也可能是 AI 写偏了。所以比对结论是"差异"，不是"错误"，最终由你裁决。

## 执行步骤

1. **收集**：读取本章用户大纲 user_outlines/NNN.md 与本章正文大纲 outlines/NNN.md。**若 user_outlines/NNN.md 不存在**：不要停在那里让用户去创建——先读取正文大纲和章节正文，推断用户可能的意图，主动起草一份用户大纲模板（结构：本章目标 / 关键事件 / 人物走向 / 禁忌项）发给用户确认；用户确认或修改后再写入 user_outlines/NNN.md。用户已手动写过大纲草稿（无论放在哪）时，直接整理成该文件。
2. **全新上下文比对**：启动 `run_subagent`（agent_type=review），指令中只粘贴两套大纲（不粘贴正文，避免长文干扰），要求：
   - 以"读者+编辑"视角逐项比对：用户大纲的每个关键点，在正文大纲里是否体现？
   - 输出三类差异：**偏离**（正文大纲与用户大纲冲突的点）、**缺失**（用户大纲要求但正文没发生的点）、**新增**（正文出现了用户大纲没提的重大情节）。
   - 每条差异标注：用户大纲原意 / 正文实际 / 可能原因 / 建议动作（改正文 或 改用户大纲 或 保持现状需说明）。
   - 只列事实差异，不下"好坏"判断。
3. **逐条处理**：把差异清单呈现给用户，逐条给出建议；用户确认后执行（改正文→走分段写作流程；改用户大纲→用户自己改或授权你改；保持现状→记录理由）。**不得未经确认擅自改用户大纲。**

## 安全边界（防止过时大纲污染正文）

本技能**只输出差异与建议，绝不直接改写正文**。正文只有在用户明确说"按大纲改"时才以大纲为依据修改；用户说"润色/优化"时，本技能不得被触发，正文以自身为准。差异清单里的"建议改正文"必须经用户逐条确认后才执行。
4. **沉淀**：处理结果（尤其"用户改主意"的条目）写入用户大纲的变更备注或 platinum.md，避免下次重复比对同一偏差。

## 触发方式

- 每章完成后自动执行一次（与章级评审一起做，节省一次子 Agent 启动）。
- 用户可随时用 `/一致性比对` 手动触发。
- 用户明确说"按我的大纲来""这里和我想的不一样"时，优先触发本技能。
